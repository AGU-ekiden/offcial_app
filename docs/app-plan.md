# 青山学院大学陸上競技部 長距離ブロック 公式アプリ企画（たたき台）

Oct 18, 2026 · @下田裕太です

公式アプリは「通知・速報・応援」でファンとチームをつなぐ場所にし、記録の公式な置き場は公式サイトに任せる。最初は4つの機能に絞り、部内テストを経てストアに公開する。

## 目的とコンセプト

アプリを入れてもらう理由は「いち早く届く」「応援がもっと身近になる」「ここでしか見られない」の3つ。サイトで見られる情報を並べるだけのアプリにはしない。

- **いち早く届く**：結果やニュースが出たら通知で届く。駅伝・大会当日は速報が見られる
- **応援がもっと身近に**：チームへの応援メッセージを送れる。チームの日常（練習・合宿・寮生活）が見られる
- **ここでしか見られない**：学内タイムトライアルの限定配信など、アプリ限定のコンテンツ

主な利用者は、すでにチームを応援しているファン、OB・OG、選手の家族。

## 公式サイトとの役割分担

サイトは「公式の記録・名刺」、アプリは「応援の場所」。迷ったら「通知・速報・応援・限定」のどれかに当てはまればアプリ、それ以外はサイトに入れる。

|  | 公式サイト | 公式アプリ |
| --- | --- | --- |
| 主に見る人 | 初めて知った人、高校生・保護者、メディア、スポンサー | ファン、OB・OG、選手の家族 |
| 開くきっかけ | 検索、SNSのリンク、調べたいとき | 通知、毎日の習慣 |
| 役割 | 正確でまとまった記録。誰でも見られる | 速く届く・参加できる |
| 載せるもの | 部の紹介、部員一覧、過去の記録、御礼、スポンサー紹介 | 新着の通知、速報、限定動画、応援メッセージ |
| お互いへの案内 | 「速報はアプリで」 | 「記録の一覧はサイトで」 |

データはどちらも同じNotionを使う。入力は1回で済み、内容がずれない。

## 学生スポーツとしての方針

主役は「誰が人気か」ではなく「このチームがどう挑み、学生たちがどう成長しているか」。プロではなく学生であることを前提に、芸能事務所のような見せ方はしない。

| やること | やらないこと |
| --- | --- |
| チームと成長（入学から卒業までの4年間）を中心に伝える | 一部のスター選手だけを大きく扱う |
| 部員は全員同じ形で紹介。マネージャー・主務・トレーナーも紹介する | 人気投票、人気ランキング |
| 学部、寮生活、学業との両立、卒業後の進路など「学生」としての顔も見せる | フォロー数や「いいね」数など、人気を数字で比べる表示 |
| 応援メッセージはチーム全体あて。個人あては部で確認してから届ける | 選手個人に直接届くコメント欄やチャット |
| 選手のフォローは「結果の通知を受け取る」だけ | 「推し」という言い方や、選手の「キャラ」を売りにする内容 |
| 限定コンテンツは練習・合宿・寮生活などチームの日常 | 選手の私生活への踏み込み |

**安全とプライバシー**

- 写真は競技中心。特に女子選手は、性的な目的の撮影・拡散の問題があるため、写真の選び方・載せ方のルールを決める
- 載せる内容は本人の了承を前提にする
- 卒業後に選手の情報をどう扱うか（残す・消す・OB・OGとして載せる）を決めておく

参考：アメリカの大学スポーツは選手を「student-athlete（学生アスリート）」と呼び、大学の公式発信はチーム中心。個人の発信は本人のSNS、という分け方が一般的。

## 最初の版の機能

最初の版は4つの機能に絞り、ログイン機能は付けない。アカウントがあると、個人情報の管理や退会機能が必要になり、ストアの審査も厳しくなるため。

| 機能 | 内容 | データの出どころ |
| --- | --- | --- |
| 新着・通知 | ニュースや結果が出たら通知。アプリ内で一覧も見られる | Notionのニュース・大会結果 |
| 大会予定・結果 | 直近の予定と最新の結果。過去の記録はサイトへのリンク | Notionの大会予定・大会結果 |
| 部員紹介とフォロー | 全員同じ形の紹介。フォローした選手の結果を通知（フォロー数は非表示） | Notionの部員 |
| 限定動画 | 学内タイムトライアルなど、チームの日常の動画 | Notionに新しくデータベースを作る |

**後回しにする機能**（使われ方を見てから追加）

- 駅伝・大会当日の速報（中継点の通過、区間順位）。当日に入力する担当者が必要
- チームへの応援メッセージ・応援スタンプ。確認の仕組みが必要
- 大会会場でのチェックイン
- グッズの案内

## 仕組み

```
Notion（部員が入力）→「本番公開」ボタン → GitHub Actions
  ├─ 公式サイトを生成 → ロリポップ
  ├─ アプリ用データ（JSON）を生成 → ロリポップ
  └─ 新着があれば Firebase で通知を送信
アプリ → ロリポップのアプリ用データを読む（Notion には直接つながない）
```

部員がNotionに入力して「本番公開」ボタンを押すと、GitHub Actionsが公式サイトとアプリ用データを作ってロリポップに置き、新着があればFirebaseで通知を送る。アプリはNotionに直接つながないため、Notionの合言葉（トークン）がアプリに入らない。

## 進め方

企画を固めて大学・部の承認を取ってから作り始め、部内テストを経て公開する。

1. **企画**：このたたき台をもとに、目的・方針・最初の機能を決める。「決めること」をすべて埋める
2. **準備**：公式サイトを更新するときに、アプリ用のデータも書き出すようにする。ストアのアカウントを登録する
3. **最初の版を作る**：新しいGitHubリポジトリを作り、Claude Codeで開発する。作り方はExpo（React Native）。1つのプログラムでiPhoneとAndroidの両方に対応する
4. **部内テスト**：TestFlight（iPhone）と内部テスト（Android）で部員だけに配り、意見を集めて直す
5. **ストア公開**：プライバシーポリシーのページを公式サイトに置き、審査に出す
6. **機能を増やす**：速報、応援メッセージなどを、使われ方を見ながら追加する

作業の場所は2つに分ける。企画・相談は claude.ai のプロジェクト「公式アプリ企画」で行い、この文書を資料として入れる。開発は新しいリポジトリで行い、この方針を `CLAUDE.md` に書いておく。

## 費用の目安

必ずかかるのはストアの登録料だけで、年間およそ1.5万円。金額はおおよその目安で、申し込み前に各公式ページで確認する。

| 項目 | 費用（目安） | 備考 |
| --- | --- | --- |
| Apple Developer Program | 年 約1.3〜1.5万円 | iPhone版をストアに出すために必要 |
| Google Play デベロッパー登録 | 初回のみ 約4,000円 | Android版をストアに出すために必要 |
| Firebase（通知） | 無料枠で足りる見込み | 通知の送信自体は無料 |
| Expo（アプリの作成） | 無料プランから始められる | 作成回数が多いと有料プランが必要になることがある |
| データの置き場 | 追加なし | 今のロリポップを使う |
| D-U-N-S番号 | 無料 | 部や大学の名義で公開する場合に必要 |

## 決めること

開発を始める前に、次の項目を決める。特に承認と名義は、あとから変えるのが大変なため最初に決める。

- [ ] 大学・部から「公式アプリ」として出す承認をとる
- [ ] ストアに出す名義を決める（個人名義だと「提供元」に個人名が出る。部・大学の名義ならD-U-N-S番号を取得する）
- [ ] 費用を誰が出すか決める
- [ ] 入力・運用の担当者を決める（ニュース、結果、限定動画、将来の速報）
- [ ] 写真のルールを決める（競技中心、女子選手の写真の扱い、本人の了承）
- [ ] 卒業後の選手情報の扱いを決める
- [ ] 最初の版の機能を確定する（この文書の4つでよいか）
- [ ] 公開の目標時期を決める（例：箱根駅伝の前に部内テストを始める）
- [ ] アプリの名前とアイコンを決める
